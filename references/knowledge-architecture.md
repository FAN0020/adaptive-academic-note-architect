# Reconstruct the learning logic

Keep a compact map: topic → prerequisites → problem/motivation → mechanism → example/evidence → applicability/limits → next concept. Attach locations and gaps to the same map. Do not generate seven separate reports.

For complex work save source quality, preferences, mode, modules as full/targeted/skip, P0/P1/P2 queue, outline and QA priorities. An optional short trace tracks completed extraction, verified gaps and revisions. Use real counts only. Keep internal unless requested.

Select the discipline's organizing logic:

- Mathematics: definitions → assumptions → theorem → proof → consequences/counterexamples → applications.
- Engineering: problem/requirements → design choices → architecture/mechanism → implementation → evaluation → trade-offs.
- Business/social science: context → framework → decision criteria → cases/evidence → limits/alternatives.
- Experimental science: question → hypothesis/model → methods → results → interpretation → uncertainty.

These are examples, not rigid templates. Preserve a good existing structure in Light mode. Never impose Agent Training concepts on unrelated courses.

## Concept introduction

Check important concepts for What, Why, How, When and Connections, then write needed pieces in connected prose. A simple definition may need one sentence; a difficult method may need motivation, notation, derivation and an example. Do not attach five repetitive headings to every concept.

Explain the unresolved problem that motivates a new method; connect its mechanism back to that problem and state applicability. Do not imply that a teaching sequence is a universal implementation requirement.

Example transition: “示范能让模型学习已有行为，但该目标没有直接比较不同尝试的任务回报。若基本流程已可靠而效果仍停滞，就需要解释如何利用结果反馈改善策略。” This motivates a transition, not a rule to introduce RL in every workflow.

## Mathematics

Preserve essential equations/derivations; define variables, units, domains and assumptions. Explain why the expression matters; distinguish exact results, approximations and teaching simplifications. Verify important arithmetic and derivation steps. Never drop conditions to shorten formulas.

Label reconstructed reasoning as explanation/supplement. Do not claim a proof or scope wider than the evidence. Add intuition alongside original technical content, not instead of it.

## Adaptive depth

A 100-page coherent source can need Light processing and lengthy notes. A few difficult lines can need deep **local** reconstruction without a domain-wide survey. Escalate only affected modules and reuse the rest of the map.

Before drafting, inspect the outline for orphan terms, late prerequisites, vague headings and duplication. Titles should name topic plus mechanism/question/decision: “轨迹 SFT 数据构造与 Loss Masking” is more useful than “继续讨论”. Stable internal outline means ready to draft, not awaiting user approval.
